> Workflows versus agents, and when an agent is worth building.

**Tracks:** AI at Work, Management, AI Leadership, Engineering, Safety & Governance · **Sources:** official OpenAI and Anthropic material, verified November 2026

## In this lesson

- Tell a fixed workflow apart from an agent
- Name the three parts of every agent: model, tools, instructions
- Decide whether a use case needs an agent at all

## Why it matters

Many teams build agents for jobs a simple workflow would do better. Both providers' foundational guides argue for starting simple and adding autonomy only when it earns its keep. This lesson gives you the vocabulary to make that call.

## Try it

1. List five tasks your team wants to automate.
2. For each, decide: single prompt, fixed workflow, or agent, and write one sentence on why.
3. Pick the one that truly needs an agent and sketch its model, tools and instructions.

## Check yourself

1. What is the main risk of choosing an agent when a workflow would do?
2. What signals tell you a task needs open-ended decision making?
3. How would you explain the difference to a non-technical executive?

## Stage 1 project

This lesson completes **Stage 1: Get started with AI**. Before you move on, finish one piece of work.

**What to produce:** A reusable AI workflow for one task you do every week, with a saved prompt and a review step.

**Example scenario:** An executive research assistant: turn a set of reports into a one-page brief you can check against the sources.

**You are ready for the next stage when:**

- [ ] You can write a prompt that gives the same quality of result three times in a row
- [ ] You have handed one multi-step task to an assistant and checked what it did
- [ ] You can explain when a task needs an agent and when a single prompt is enough
